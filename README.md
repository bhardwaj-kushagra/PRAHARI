# PRAHARI-SIM 1.0

A local simulator and dashboard for the FIRENET–PRAHARI wildfire-detection system: a network of low-cost gas
sensors in a forest, the PRAHARI detection method at the node and at the edge, and the baselines it is compared with.

- The engine simulates weather, fires, smoke, sensors, radio and energy.
- The dashboard replays the recordings with the evidence behind every alarm.

**Every number it shows is simulation output (SIM), not field data.**

Release 1.0 is complete: all phases of [`docs/SPEC.md`](docs/SPEC.md) §7 are accepted, and the audit that locked the
release is described in [`docs/journey/release-1.0-audit.md`](docs/journey/release-1.0-audit.md).

## Run the demo (no engine, no internet)

```text
scripts/demo.sh            # macOS and Linux; Windows: double-click scripts\demo.cmd
```

The browser opens the conference storyboard in presenter mode: keys 1–9 for the steps, F for full screen. Before
a talk, follow [`DEMO_CHECKLIST.md`](DEMO_CHECKLIST.md).

## Install exactly as released

```text
pip install -r engine/requirements-lock.txt -e "engine[dev,server]"   # Python 3.11: the tested package versions
cd dashboard && npm ci                                                  # Node 20 or later: the tested package-lock
```

## Check that it still works as released

```text
scripts/check_all.sh           # tests, type check, build, doc links, every recording regenerated byte for byte
scripts/check_all.sh --quick   # without regenerating recordings
```

## Use it

```text
prahari run --config configs/scenarios/smoke.yaml --out recordings/smoke.prs.jsonl.gz   # simulate a scenario
prahari experiment --preset golden --jobs 4                                             # the evaluation protocol
cd dashboard && npm run dev                                                             # the dashboard
```

Every scenario, preset and command is listed in [`docs/guide/04-setup.md`](docs/guide/04-setup.md).

## Further development

The project was built with an AI coding agent under the rules in `CLAUDE.md`:

- stubs stay;
- contracts only gain fields;
- accepted work is not rewritten;
- no result is hard-coded.

Any change should keep those rules and end with `scripts/check_all.sh` passing. A change that alters simulator output must say why in `DECISIONS.md`. The prompt pack in `docs/SPEC.md` §12 still applies.
